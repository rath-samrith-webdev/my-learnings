## Learning Priority

When deciding what to learn next, prioritize:

```text
1. Current project requirements
        ↓
2. Weak fundamentals
        ↓
3. Skills that unlock other skills
        ↓
4. Production engineering
        ↓
5. Interesting / experimental topics
```

---

## Learning Cycle

Every important topic should go through:

```text
Understand
    ↓
Practice
    ↓
Build
    ↓
Debug
    ↓
Document
    ↓
Review
```

---

## Weekly Review

At the end of each week:

### Ask

* What did I learn?
* What did I build?
* What became easier?
* What still confuses me?
* What mistakes did I make?
* What should I practice next?
* Did I spend too much time consuming content?

---

## Monthly Review

At the end of each month:

### Evaluate

* Skills improved
* Projects completed
* Major concepts understood
* Weak areas
* Repeated mistakes
* Learning efficiency
* Next month's primary focus

---

## Rules

### Rule 1 — One primary focus

Don't spread attention across too many technologies.

### Rule 2 — Every major topic needs practice

No topic should remain theory-only.

### Rule 3 — Build projects

Projects are evidence of learning.

### Rule 4 — Track weaknesses honestly

The skill matrix should represent actual ability, not confidence.

### Rule 5 — Review old knowledge

Learning is not linear.

Some topics need multiple passes.

---

## Definition of "Learned"

A topic can be considered reasonably learned when I can:

* Explain it without notes
* Implement it without copying
* Debug common problems
* Recognize when to use it
* Recognize when NOT to use it
* Apply it in a project
* Explain the trade-offs
